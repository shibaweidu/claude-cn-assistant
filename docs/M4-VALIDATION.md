# M4 汉化核心与受管副本

日期：2026-11-27。汉化核心、制作任务和启动注入已接入；完整真实客户端制作与启动仍待退出 Claude 后验收。

## 已实现

- 提取上游中文词表、页面语言 shim 和 ASAR 处理器；来源见 THIRD_PARTY_NOTICES.md。
- Windows ion-dist.asar 布局：加入词表、更新语言白名单、注册 i18n meta、重算变动条目完整性；未知语言协商格式停止处理。
- 从用户选中的原版安装只读复制到 UUID 暂存目录，拒绝源重解析点/符号链接；字节进度、复制阶段取消。
- 原版 exe、ion-dist.asar 与 app.asar 哈希检查，发现制作期间源更新则拒绝提交。
- 仅修改暂存 exe 的 inspector 与 ASAR 完整性 fuse；不会修改安装目录中的 exe。界面明确提示副本数字签名失效。
- 校验后备份旧 managed，再切换新目录；目录替换失败尝试恢复旧副本。写入副本收据，保留备份和失败暂存目录，不自动递归删除。
- 启动时验证 exe、ASAR、app.asar、汉化脚本与内置资产一致。需要外部 Node.js 22+；没有隐式下载安装运行时。
- 本机回环临时 inspector 端口；校验进程 execPath 后才注入；确认汉化 hook 与至少一个目标页面注入，随后关闭 inspector。未确认时返回失败并尝试结束本次启动的子进程，不强杀既有 Claude。
- hook 只针对默认 session、窗口/webview 及 Claude HTTPS 或本地 app 页面，不引入语音、权限处理器、Computer Use、插件或网关。
- 安装与汉化操作互斥，冲突返回忙碌错误而非阻塞 UI。用户下载源仍为指定镜像 GitHub Releases，没有新增原版客户端官方下载入口。
- 桌面汉化页提供制作确认、真实复制进度、取消、数据目录与启动按钮。桌面文案的“官方客户端”改为“原版客户端”。

## 实际验证

- 核心测试：26 项通过，1 个上游 macOS 本机测试忽略；包含 ASAR 幂等性、未知格式不改文件、fuse 仅修改指定字节与词表 JSON。
- npm run check、脚本 node --check、cargo clippy（-D warnings）、前端构建及内嵌桌面构建通过。
- cargo run -p assistant-core --example localization_probe：对本机 6.6395.0 的 ion-dist.asar 复制到临时目录后实际汉化并校验通过，原资源 SHA256 未变化。
- 完整副本制作联调：当前检测到 Claude 正在运行，正确拒绝制作，没有强制退出或修改原版安装。
- 没有进行完整副本实际启动，因此未验证真实中文窗口、单实例行为、启动注入时序和 inspector 关闭的正向结果，不能宣称中文版已经可用。

## 当前限制与后续

- 仅支持 Windows ASAR 布局；目录形态、macOS/Linux 汉化后续实现。
- 开发版依赖外部 Node 22+；正式发布需内置受校验运行时。
- 使用前需正常退出所有 Claude 进程。当前不自动关闭用户应用。
- 失败暂存和备份保留，可能占用较多磁盘；下一阶段提供可视化备份恢复与清理。首次制作失败无可启动副本；再次制作失败会保留旧文件，但当前任务状态为失败，恢复入口尚未实现。
- 事务中断仅标记 interrupted，不自动猜测完成；恢复与更完整收据校验属于 M5。
- 页面注入确认不等于全部中文覆盖。需真实窗口逐项检查本地页和远端页。
- 页面运行使用 Claude 自身账户与用户数据；此实现未主动写 Claude 语言配置文件或回滚对话。

诊断日志：应用数据目录 localization-launch.log；副本 cn-runtime/hook.log。只读资源探测不会启动应用；prepare_localized 示例会显式制作受管副本，运行中拒绝。
